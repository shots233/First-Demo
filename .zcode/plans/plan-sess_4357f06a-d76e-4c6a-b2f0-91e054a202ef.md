为主角 AnimBP 添加“是否持剑”布尔驱动（C++ 部分由我实现；ABP 连线由你在编辑器完成）。

## C++ 改动（2 个文件，照现有风格）

### 1. Source/First/Public/AnimInstances/FirstDKAnimInstance.h
在 `MoveRight` 之后新增（与 bIsTargetLocked 等同款声明风格）：
```cpp
// 当前是否手持武器。AnimBP 用它选择持剑/空手的站立与移动姿态分支。
// 装备状态唯一事实来源是 DKCombatComponent 的 CurrentEquippedWeaponTag，
// 动画层不自行记录，避免与装备/收剑流程不同步。
UPROPERTY(VisibleDefaultsOnly, BlueprintReadOnly, Category="AnimData|State")
bool bWeaponEquipped = false;
```

### 2. Source/First/Private/AnimInstances/FirstDKAnimInstance.cpp
- 新增 include：`Components/Combat/DKCombatComponent.h`、`MyGameplayTags.h`；
- `NativeThreadSafeUpdateAnimation` 中与 bIsTargetLocked 等一起先重置 `bWeaponEquipped = false;`，随后在 `if (DKCharacter)` 块内填充：
```cpp
// 装备状态只在持剑时有效；空手时 CurrentEquippedWeaponTag 已被清空。
const UDKCombatComponent* Combat = DKCharacter->GetDKCombatComponent();
bWeaponEquipped = Combat &&
    Combat->CurrentEquippedWeaponTag == MyGameplayTags::DK_Weapon_Sword;
```
（读取方式与 GA_DKGuardParry::CanActivateAbility 对同一字段的判断完全同口径；ThreadSafe 阶段只读该成员，无数据竞争。）

### 3. 编译验证
改的是头文件属性（类布局变化），Live Coding 不可靠：我尝试 UBT 编译，若编辑器开着会被拦；届时你需要关编辑器完整 Build 一次再重开。

## ABP 操作指引（你在编辑器里做，我给精确节点级步骤）
1. 打开 ABP_DK_Sword → 双击 Locomotion → Idle 状态（当前：A_DK_Sword_Idle → Output）；
2. 把 `Content/IK/Source/DK/AS_Idle_Seq` 拖入图表，生成 Sequence Player（确认它骨架同为 SK_Mannequin_Skeleton，若报错需先重定向，告诉我我再出方案）；
3. 添加 **Blend Poses by Bool（按布尔混合姿势）** 节点：
   - Index 0（False）= AS_Idle_Seq 的 Sequence Player（空手）；
   - Index 1（True）= A_DK_Sword_Idle 的 Sequence Player（持剑）；
   - 输出接 Output Pose；
   - Active Value 引脚：细节面板勾选变量后从左侧“我的蓝图”拖入 `bWeaponEquipped`（现在它在 Variables 面板可见，类型 Boolean，只读）；
   - Transition Time 建议 0.3s（装备/收剑蒙太奇会盖住切换瞬间，实际几乎看不到混合过程，主要是防止边缘情况硬切）。
4. 保存 ABP → PIE：按切换键，站立姿态应随持剑/空手切换；受击、攻击、锁定移动均不受影响（只动了 Idle 内部）。

## 验收
- 持剑站立 = A_DK_Sword_Idle、空手站立 = AS_Idle_Seq；装备/收剑动画结束后姿态正确落位；
- C++ 侧新增 bool 为只读派生态，不改任何 gameplay 逻辑、无行为回归风险。
